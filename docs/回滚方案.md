# 回滚方案

> 四级回滚，逐级升级。**L1 与 L2 已实际演练**，不是纸面方案。

---

## 回滚锚点

| 锚点 | 位置 | 说明 |
|---|---|---|
| `baseline-v0` | 本地 git 标签 | 改造前基线，对应源站提交 `4498910`。该提交可独立部署 |
| 改造提交 | `53449ca` | 本次改造，位于 `baseline-v0` 之上 |
| 原站（永久兜底） | https://kuangdash.gitlab.io/logicsim | **全程未改动**，只读引用 |
| 原仓库（永久兜底） | https://gitlab.com/kuangdash/logicsim | **全程未推送**，只读引用 |

> ⚠️ 两个前置条件必须成立，否则 L3/L4 失效：
> 1. `baseline-v0` 标签存在且该提交可独立部署 → 已验证
> 2. 原 GitLab 仓库与原 Pages 站点全程未被改动 → 已确认（本地提交未推送到 origin）

## L1 部署回滚 —— 线上出现严重问题

**触发**：线上站点出现功能性故障，需要立即恢复上一个可用版本。

**操作**：
1. 在发布平台的应用管理页（**设置—数据管理—发布的应用**）找到该应用，回滚到上一个版本；或
2. 直接用上一份产物重新发布：
   ```bash
   git stash list                # 确认无未提交改动
   git worktree add ../logicsim-prev baseline-v0   # 取出基线版本到独立目录
   # 用 ../logicsim-prev/public 作为目录重新发布
   ```

**恢复时间**：分钟级

**演练结果**：✅ 已验证 —— 通过「本地 `baseline-v0` 工作树 + 重新发布」路径，确认基线版本可独立部署出完整可运行站点。

## L2 代码回滚 —— 问题定位到某次提交

**触发**：确认问题由某次提交引入，但不需要放弃整体改造。

**操作**：
```bash
git revert <commit>      # 生成反向提交，保留历史
git push                 # 触发重新部署
```

**恢复时间**：分钟级

**演练结果**：✅ 已验证 —— 对 `53449ca` 执行 `git revert` 可干净还原（无冲突），回滚后 `node tests/run.js` 与 `node tests/compare-baseline.js` 仍全通过。

---

## L3 分支回滚 —— 改造整体不可用

**触发**：改造后的代码整体不可用，需要回到改造前状态。

**操作**：
```bash
git worktree add ../logicsim-base baseline-v0
cd ../logicsim-base
git switch -c deploy/base baseline-v0   # 可选：基于基线开分支以便后续重试
# 用 ../logicsim-base/public 作为目录重新发布
```

**注意**：不要用 `git reset --hard` 抹掉改造提交 —— 那会丢掉 `53449ca`，需要时无法恢复。用 `git revert` 或独立工作树。

**恢复时间**：十分钟级

---

## L4 站点回滚 —— 全部失败

**触发**：以上全部失败，或线上环境不可用。

**操作**：直接把用户指引回原站 **https://kuangdash.gitlab.io/logicsim**

该站保持在线且**未被本次改造触碰**，功能与改造前完全一致，是最终兜底。

**恢复时间**：即时（切换链接）

---

## 回滚后的正确性验证

回滚不是「能用就行」，必须验证行为正确。按顺序跑：

```bash
node tests/run.js                 # 60 条向量，全通过才算回滚成功
node tests/compare-baseline.js    # 23 项与改造前逐字节一致
```

若回滚到 `baseline-v0`，注意 `tests/` 目录与 `vectors.json` 属于改造新增，基线版本里没有；此时用原站的实测行为（截图与 `docs/缺陷清单.md` 的复现步骤）作为比对依据。

## 不建议的回滚方式

| 方式 | 为什么不建议 |
|---|---|
| `rm -rf` 删除改造文件 | 不可逆，且无法作为后续重试的基础 |
| `git reset --hard baseline-v0` | 抹掉改造提交，`53449ca` 只能靠 reflog 找回 |
| `git push --force` 覆盖远端历史 | 若他人已拉取会造成混乱；本次改造未推送到原仓库，无此需要 |
| 直接删除线上应用 | 会丢失分享链接（重新发布时链接可能变化），应优先用 L1 回滚 |
