## 3A 输入健壮性重构

### 问题

`LogicParser` 把「合法结果」与「错误信息」都用 `string` 返回，上层 `app.parseLogic` 用 `typeof result === 'string'` 判定错误。于是：

- `a`（单变量）→ 报红字错误 `a`，无法出图
- `1` / `0`（常量）→ 报红字错误，而 `ModelGen` 里对应分支是死代码
- `"   "`（纯空白）→ 返回 `undefined`，绕过判定 → `ModelGen(undefined)` → **未捕获 TypeError，页面崩溃**
- `a b`（无尾空格）→ 静默丢弃变量 `a`

### 改动

1. **返回契约改为统一结果对象**
   ```js
   { ok: true,  tree, quant: [{var, type}] }
   { ok: false, code: "E_EMPTY", message: "表达式为空：请输入逆波兰逻辑表达式。" }
   ```
   错误码与中文文案集中在 `LOGIC_ERRORS`，共 8 个：`E_EMPTY` / `E_ARITY_LOW` / `E_ARITY_HIGH` / `E_QUANT_TARGET` / `E_TOO_MANY_VARS` / `E_TOO_MANY_PATHS` / `E_BUDGET` / `E_INTERNAL`。

2. **结尾未结算变量提交** — 循环结束后若仍有一个变量待提交，先提交再校验栈深，修掉 `a b` 静默丢弃。

3. **栈校验收紧** — 最终必须恰好剩 1 个元素且 `nstate === 1`，否则报 `E_ARITY_LOW` / `E_ARITY_HIGH`。

4. **放宽操作符紧邻** — 遇到操作符时若栈顶有待提交变量，先提交。于是 `a b.` 与 `a b .` 等价（原先报错）。注意 `a.b` 仍被正确判为错误（RPN 里 `.` 之前需要两个操作数）。

5. **`ViewGen0` 补防御** — 找不到公共根变量时返回带 `error` 标记的空图，而不是 `undefined`。上层转成中文提示。（暴力搜索 11,868 个合法表达式未命中该分支，属理论风险，但量词会改变路径集形态，故补上。）

6. **三重规模上限**
   - `MAX_VARS = 8` — 变量数上限
   - `MAX_PATHS = 4096` — 化简后路径数上限
   - `MG_BUDGET = 200000` — `ModelGen` 内部步数预算，超限抛 `LogicBudgetError`，上层转 `E_BUDGET`

   目的是让指数爆炸**可见且可控**，而不是页面静默卡死。

### 为什么先做这一步

量词会引入新的「结果可能是字符串」路径（例如 `z ?` 作用在不含 `z` 的表达式上）。若不先重构返回契约，C1~C4 那批 bug 会原样复发。

## 3B 全称 / 存在量词

### 语法设计

新增两个**后缀一元算子**，沿用原有「压栈即归约」风格：

| 记法 | 含义 |
|---|---|
| `<表达式> <变量名> ?` | ∃ 存在量词 |
| `<表达式> <变量名> !` | ∀ 全称量词 |

例：`a b . x ?` = ∃x.(a ∧ b)；`a b , a !` = ∀a.(a ∨ b)。

**为什么用 `?` / `!` 而不是字母 `E` / `A`**：分词器的 `else` 分支把任何非操作符 token 都当变量名。若把 `E`、`A` 定义成操作符，名为 `E` 或 `A` 的变量就永久无法使用 —— 这是破坏性变更。而 `?`、`!` 与现有五个操作符一样都是非字母符号，零命名冲突。

### 求值规则

```
∃x φ  ≡  φ[x:=0] ∨ φ[x:=1]
∀x φ  ≡  φ[x:=0] ∧ φ[x:=1]
```

在 `LogicParser` 里实现为：对栈顶弹出的表达式做变量代入（`substVar`），再用既有的 `orM` / `andM` 组合。

```js
var v0 = substVar(body, bound, "0");
var v1 = substVar(body, bound, "1");
stack.push(("exists" === type) ? orM(v0, v1) : andM(v0, v1));
```

**为什么不走恒等捷径**：一度加过「绑定变量未出现时直接返回原表达式」的优化。实测发现它会让已量化的公式在栈上还原成裸字符串，从而在语法上**伪装成变量名**，使 `?` / `!` 接受本该拒绝的输入（如 `a a b ? !`）。实测确认 `ModelGen` 对恒等情形幂等（`orM(φ,φ)` 与 `andM(φ,φ)` 的化简结果与 `φ` 完全一致），因此去掉捷径不改变任何输出，只换取语法严格性。

未真正绑定到变量的量词（绑定变量不出现在表达式里）语义上是恒等变换，**不记入 `quantLog`**，因此不会出现在界面的量词前缀里。

### 界面展示

1. **量词前缀条** — 画布左上角的只读浮层（`pointer-events: none`，不拦截画布交互），按「由外到内」顺序列出，如 `量词前缀 ∃a ∀b`。不含量词时显示「本表达式不含量词」。
2. **状态栏** — 解析成功后追加绑定数量，如「（已绑定 1 个量词）」。
3. **规模统计** — 状态栏右侧显示「变量 2 · 路径 3」，让指数增长对用户可见。
4. **模型 JSON 顶层可选字段 `quantPrefix`** — 保证「解析 → 图转文本 → 文本转图」往返不丢量词信息。

### ⚠️ 实现期对计划的一处修正

计划原定给「被量词绑定的变量」在 `Import` 节点上加角标（`∀x` / `∃x`）。实现期验证发现该设想**在语义上不成立**：

```js
LogicParser('a b , a !')   // quant: [{var:'a', type:'forall'}]
ModelGen(...)              // order: ['b']   ← a 已被消去
```

量词会**消去**被绑定变量，因此结果图里不存在该变量的 `Import` 节点，也就没有节点可打角标。更糟的是，若变量被消去后又以自由变量身份重新出现（如 `a b , x . x ? x ,` 中的第二个 `x`），角标会把它**误标**为「已绑定」。

因此改为：**量词信息不进入节点结构**，由前缀条与顶层 `quantPrefix` 字段承载。这也让 `ViewGen` 的输出契约保持与改造前完全一致（无条件逐字节兼容），比原方案更稳。

### 兼容性风险与处理

| 风险 | 等级 | 处理 |
|---|---|---|
| 分词器把 `?`/`!` 当变量名 | 中 | 同步更新分正则 `/(\.\|,\|<\|>\|=\|\s)/` → 追加 `\?\|\!` |
| 路径枚举指数爆炸被量词放大 | **高** | 三重上限（变量 8 / 路径 4096 / 计算量 200000），超限给中文提示而非卡死 |
| 旧 JSON 载入新版本 | 低 | `quantPrefix` 为可选顶层字段，缺省即「无量词」 |
| `?` / `!` 破坏既有表达式 | 低 | `?`、`!` 原先不属于任何合法 token（会被当成变量名的一部分），现有 60 条向量全通过 |

## 3C 现代 UI 与响应式

### 改动

1. **Flexbox 重写页面骨架** — 淘汰 `float:left` + 固定百分比宽度。`.joint-app` 改为纵向 flex（头部 + 主体），`.app-header` 内部横向 flex（小地图 + 工具区）。
2. **CSS 变量** — 配色、尺寸、圆角全部抽成 `:root` 自定义属性（约 30 个）。
3. **行内样式外移** — 原 `index.html` 里大量 `style="..."` 与 `w3-*` 工具类全部移入 `style.css`，停止引用 `w3.css`。
4. **三档响应式断点**
   | 断点 | 布局 |
   |---|---|
   | `> 1180px` | 三栏：工具区 + 画布 + 右侧面板（300px，可拖拽调宽） |
   | `640 – 1180px` | 右侧面板收窄到 260px |
   | `≤ 900px` | 上下堆叠：画布在上 55%，面板在下；隐藏小地图与拖拽条 |
   | `≤ 560px` | 工具区进一步压缩，示例按钮换行 |
5. **解析后立即出图** — 原站是两步流程（解析只产 JSON，还需再点「文本转图」），实测会让人以为解析没生效。改为解析后直接渲染；「文本转图」按钮与手工改 JSON 的用法完全保留，**能力只增不减**。
6. **中文错误提示** — 状态栏三态配色（成功绿 / 失败红 / 信息灰），替代英文报错与 `alert` 弹窗。
7. **无障碍与体验细节** — 尊重 `prefers-reduced-motion`；控件加 `:focus` 可见焦点环；示例快捷按钮便于上手量词语法。

### ⚠️ 保留绝对定位的部分（重要）

画布区**没有**改成 Flex。`.main-container`、`#app-resize`、`.right-container`、`#paper-container` 的 `left/top/right/width` 会被 JS 直接改写，是平移、缩放、面板拖拽与折叠的计算基准：

- `paperContainer.css({left, top})` — 画布平移
- `rightContainer.css({width})` / `appResize.css({right})` / `mainContainer.css({right})` — 面板拖拽
- `setContainerAndMini()` — 小地图视口框

把它们换成 Flex 会破坏这些不变量。因此采取「**骨架 flex 化、承重区保持绝对定位**」的分层策略，并在 `style.css` 顶部以注释列明**不可改动的标识符清单**。

窄屏下面板改为全宽堆叠时，用 `!important` 覆盖 JS 写的行内 `width`/`right`，同时 `app.ResizeBlock()` 在窄屏直接 `return`，避免两套规则打架。

### 响应式重排机制

```js
$(window).on("resize orientationchange", scheduleRelayout);  // 160ms 防抖
```

`relayout()` 只做 `fitToContent` + 容器/小地图同步 + 重新居中，**不重跑 dagre 布局**（节点位置已算好，重跑是无用功且可能改变图形）。

### `joint.js` 不升级的原因

`lib/` 目录全程冻结。原仓库同时存在 `joint.js`（完整版）与 `joint.min.js`，实测 **min 版是残缺构建** —— 缺少 `shapes.standard`、`elementTools.Remove`、`linkTools.Boundary`，而这三个都是本项目必需的。因此删掉 min 版、保留完整版，且不升级到 JointJS v4（存在 `shapes.standard` API 变更 + 许可条款变化双重风险，而本次改造完全不需要动图形库）。

## 本轮落地的改动

### 1. 中缀输入（降低输入门槛）

新增 `public/InfixParser.js`：递归下降解析中缀表达式 → 运算符 AST → 后缀串。

**关键设计：翻译成后缀后复用完全相同的既有管线。** 因此

- 下游（ModelGen / ViewGen / GateViewGen / 量词）**零改动**，不可能引入回归
- 量词能力自动可用（`∀x(a AND b)` → `a b . x !`）
- 两种写法天然等价，由 6 组对照用例守着

支持 `NOT/!`/`~`/`¬`、`AND/&&/&/∧/·/*`、`OR/||/|/∨/+/,`、`->/=>/IMPLY/→`、`<->/<=>/IFF/↔/≡`、`∀x()/ALL x()/FORALL x()`、`∃x()/EX x()/EXISTS x()/SOME x()`。
优先级 `¬ > ∧ > ∨ > → > ↔`，推出右结合。

**刻意不用 `E`/`A` 当量词符号**（与后缀模式同一个理由：会永久占用两个变量名）。

错误带**字符位置**（`index` / `length`），供界面在输入框下方画指位符。为此也给后缀解析器的错误补了可选的位置字段（`logicErr(code, token)`），让两种记法的报错都能定位。

### 2. 实时预览 + 内联报错

- 输入框 `input` 事件 → 400ms 防抖 → 自动解析出图
- **失败时保留上一张图**：用户打到一半语法必然不完整，此时清空画布是灾难性体验，所以只在输入框下标红并画指位符，画面不动
- 错误位置用 `预格式文本 + ^ 指位符` 展示，比只给一句话清楚得多

### 3. 逻辑门视图（本轮最大的一块）

反馈说"节点就是一个空方块，看不出是什么逻辑门"。这里有个**语义前提必须先讲清楚**：

> 选择器视图画的是**化简后**的 MUX 网络，图上**根本不存在**与门/或门/非门节点 —— 所以"把 SEL 节点换成与门符号"是错的，会误导人。

正确做法是**新增一个视图**，从**原表达式**直译成门电路：

```
                ┌─► ModelGen ─────► 路径集 ────► ViewGen ──────► 选择器视图（SEL 网络）
LogicParser ────┤
                └─► 运算符树 {op,a,b} ──────────► GateViewGen ──► 逻辑门视图（与/或/非门）
```

实现要点：

- **参数化 `LogicParser(rpn, opts)`**：`opts.nodeKind==='gate'` 时节点构造子从 `{S,"0","1"}` 换成 `{op,a,b}`。为此把 `substVar` / `occursIn` / `collectVars` 改成**按节点形状多态**，量词的代入消去逻辑只写一次、两种表示共用。默认行为一字未改（基线比对 23/23 依旧全通过）。
- **`opts.keepQuantifier`**：门视图保留量词节点。不保留的话 `∀a(a∨b)` 会被展开成 `(0∨b) ∧ (1∨b)`，形状读不懂。
- **标准逻辑符号**：与门 D 形（`M0,0 L50,0 A34,34 0 0 1 50,68 L0,68 Z`）、或门月牙形（三段二次贝塞尔）、非门三角 + 圆。推出/等价不是基本门，按电路图惯例用带符号的方框。
- **类型名与选择器视图隔离**：门视图的常量/输出用 `CONST0`/`CONST1`/`GateOut`，变量统一用 `VAR`。原因：选择器视图也用 `"0"`/`"1"`/`"Export"`，名字撞车会让 `nodeCreate` 无法判断该走哪套渲染。
- **渲染基类**：必须用 `joint.shapes.standard.Path` / `standard.Rectangle`，不能直接 `new joint.dia.Element` —— 后者没有合法的 `type` 字符串，`graph.resetCells` 会报 "cell type must be a string"。

### 4. 真值表

`TruthTable(vars, cubes)`：变量取**化简后函数的自由变量**（被量词消去的变量不是自变量，列出来没意义）。

**位序踩过的坑**：一开始 `bits[i] = (m >> i) & 1` 让 `vars[0]` 成了最低位，表看起来是 `000,100,010,110...` 而不是习惯的二进制计数顺序。改成 `(m >> (n-1-i)) & 1`，让第一列变化最慢。

**一个容易搞错的量**：`ModelGen` 输出的 `value.length` 是**立方体（蕴含项）条数**，不是**满足赋值个数** —— 一个立方体可以覆盖多个赋值。测试里我一度把 `a b . fe ge > =` 的期望真值数写成 9（那是路径数），实测正确答案是 6。已用独立暴力求值确认，并把这条写进测试注释。

### 5. 导出 SVG / PNG

**JointJS v3.3.1 这个构建里没有 `paper.toSVG`**（实测 grep 为 0），所以自己实现：

1. 克隆画布 SVG，删掉网格层
2. 用 `paper.getContentBBox()` 裁到内容范围 + 24px 内边距
3. 插一层白底 rect（SVG 本身无背景，贴到深色背景上会糊）
4. **把 `<image>` 的外部引用内联成 data URI** —— 不内联的话，导出的独立 SVG 里相对路径会断链，PNG 经 canvas 绘制时也会被判为跨源污染而直接失败
5. SVG 直接下载；PNG 走 `Image` → `canvas`（2 倍分辨率）→ `toBlob`

### 6. 手动添加节点与连线

- `paper` 开启 `linkPinning: false`（拖到空白丢弃，不留悬空线头）、`snapLinks`、`markAvailable`、`interactive.arrowheadMove`（拖端点改接）
- `validateConnection`：只允许**输出端 → 输入端**，不允许自环
- 端口方向靠端口分组判断（`in` / `out`），两种视图的端口命名统一
- **踩过的坑**：门节点最初把端口分组命名成 `gin` / `gout`，而 `isOutputPort` 判定的是 `"out"` —— 结果门节点的连线校验永远返回 false，手动连线完全不能用。已统一为 `in` / `out`，并由端到端测试直接调 `validateConnection` 守着（合法=true、同节点=false、反向=false）。

## 本轮的经验教训（都写进测试了）

1. **自动化期望值本身也会错。** 真值表那条把"路径数"当成"满足赋值数"，失败后先用独立暴力求值确认哪边对，再改测试——而不是改实现去迎合测试。
2. **测试写错会和真 bug 混在一起。** 门视图结构检查最初用"入边数"判断变量节点是否有连接，方向搞反了（变量是数据源，只有出边），15 例全红。诊断时先分清是实现的错还是断言的错。
3. **命名不一致是静默杀手。** `gin`/`gout` vs `out`/`in` 不会报错，只会让功能"看起来不行"。这类跨模块的枚举值必须有测试直接断言。
