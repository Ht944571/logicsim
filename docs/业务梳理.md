# 业务梳理

> 对象：`logicsim`（原站 https://kuangdash.gitlab.io/logicsim ｜ 源仓库 https://gitlab.com/kuangdash/logicsim）
> 依据：对部署版与源仓库的实际抓取，以及把纯逻辑层抽出在 Node 中运行的行为验证。非代码阅读推测。

## 1. 业务功能边界

一句话概括：**把逆波兰记法的命题逻辑表达式编译成一棵由选择器（MUX）构成的图形化电路，并支持图与 JSON 双向转换。**

| 功能 | 入口 | 改造前 | 改造后 |
|---|---|---|---|
| **中缀表达式输入** | 记法切换 + `InfixToRPN()` | 不存在 | **已支持**（自动翻成后缀走同一管线） |
| **打字即出图** | 输入框 `input` 防抖 400ms | 不存在 | **已支持**（语法不完整时保留上一张图） |
| **逻辑门视图** | 视图切换 + `GateViewGen()` | 不存在 | **已支持**（与/或/非门标准符号） |
| **真值表** | 真值表页 + `TruthTable()` | 不存在 | **已支持** |
| **导出 SVG / PNG** | 工具栏 | 不存在 | **已支持** |
| **手动添加节点 / 连线** | 工具栏 + 端口拖拽 | 不存在 | **已支持**（连线带方向校验） |
| **本机持久化** | `localStorage` | 不存在 | **已支持**，界面明确说明去向 |
| 文本 → 模型 JSON | 「解析」`app.parseLogic()` | 仅产出 JSON | 产出 JSON **并立即出图** |
| 模型 JSON → 图形 | 「文本转图」`app.load()` | 可用 | 可用 |
| 图形 → 模型 JSON | 「图转文本」`app.save()` | 可用（改名后类型会丢） | 可用（类型不再丢） |
| 从本地文件载入 JSON | 「载入文本」 | 可用 | 可用（增加读取失败提示） |
| 导出 JSON 到本地 | 「保存文本」 | 可用 | 可用 |
| 元素标签/备注编辑 | `app.ChangeName()` | 可用（未选中时抛异常） | 可用（未选中给提示） |
| 画布交互 | 拖拽/缩放/小地图/删除/高亮 | 可用 | 可用 |
| 节点类型角标 | — | 无 | 无（原因见下） |
| **真值表 / 变量赋值求值** | — | 不存在 | 不存在 |
| **量词（∀ / ∃）** | — | 不存在 | **已支持** |

**关于「节点量词角标」**：计划阶段设想给「被量词绑定的变量」在 `Import` 节点上加角标。实现期验证发现该设想在语义上不成立 —— 量词会**消去**被绑定变量（`a b , a !` 的结果变量集是 `[b]`，不含 `a`），因此结果图里根本不存在该变量的 `Import` 节点。而且如果变量被消去后又以自由变量身份重新出现，角标会误标成「已绑定」。故量词信息改由两处承载：画布左上角的**量词前缀条**，以及模型 JSON 的**可选顶层字段 `quantPrefix`**。

## 2. 三段式数据管线

```
 ┌───────────────────────────────────────────────────────────────────┐
 │ ① 输入层    <textarea id="ReversePol">                            │
 │   操作符： . 与   , 或   < 非(一元)   > 推出   = 等价              │
 │            ? 存在量词 ∃      ! 全称量词 ∀        ← 改造新增        │
 └────────────────────────────┬──────────────────────────────────────┘
                              │ app.parseLogic()
                              ▼
 ┌───────────────────────────────────────────────────────────────────┐
 │ ② LogicParser(expr)  —— 语法分析 → MUX / ite 树                   │
 │   分词： expr.split(/(\.|,|<|>|=|\?|!|\s)/)                        │
 │   算法： 单栈求值（后缀式天然适配），每归约一个操作符立即建节点      │
 │   节点： { S: 选择子, "0": 低分支, "1": 高分支 }，叶子为字符串      │
 │          "0"/"1" 是常量，其余字符串是变量名                         │
 │     andM(a,b)   = {S:a, 0:"0", 1:{S:b,0:"0",1:"1"}}               │
 │     orM(a,b)    = {S:a, 0:{S:b,0:"0",1:"1"}, 1:"1"}               │
 │     notM(a)     = {S:a, 0:"1", 1:"0"}                             │
 │     infM(a,b)   = {S:a, 0:"1", 1:{S:b,0:"0",1:"1"}}               │
 │     equalM(a,b) = {S:a, 0:¬b, 1:b}                                │
 │   量词： ∃x φ = φ[x:=0] ∨ φ[x:=1]                                 │
 │          ∀x φ = φ[x:=0] ∧ φ[x:=1]                                 │
 │   返回： { ok:true, tree, quant:[{var,type}] }                     │
 │      或  { ok:false, code, message }                              │
 │                                                                   │
 │   ⚠️ S 字段装的是【整棵子表达式】而非变量名                        │
 │      → 这是 MUX 树，不是严格的 Shannon 展开 / BDD，               │
 │        不要套用 BDD 的变量定序与唯一表概念                         │
 └────────────────────────────┬──────────────────────────────────────┘
                              ▼
 ┌───────────────────────────────────────────────────────────────────┐
 │ ③ ModelGen(tree)  —— 展开 + 归约 → 路径集                         │
 │   契约： { value: [ { ".":">"|"<", <变量名>:">"|"<", ... } ],      │
 │            order: [变量名, ...] }                                 │
 │     · "." 是【终结标记】：">" 该路径输出 1，"<" 输出 0             │
 │       （与 AND 操作符同符号，纯属命名巧合，易误读）                 │
 │     · value 是立方体（cube）集合，每条路径即一个蕴含项              │
 │   算法： 递归展开 + 交集合并；用 Set 求 order 交集并检测取值冲突    │
 │   归约： 若所有路径都终结于 ">" → 塌缩为常量 1                     │
 │          若都终结于 "<"        → 塌缩为常量 0                     │
 │   ⚠️ 复杂度：路径枚举式，最坏 2ⁿ 条路径 → 全站性能瓶颈              │
 │      （改造后由 mgSteps 预算兜底，超限抛 LogicBudgetError）         │
 └────────────────────────────┬──────────────────────────────────────┘
                              ▼
 ┌───────────────────────────────────────────────────────────────────┐
 │ ④ ViewGen(pathSet)  —— 路径集 → 图模型                            │
 │   契约： { nodeArray:[{key,type,name}], linkArray:[{from,frompid,  │
 │            to,topid}] }   ← 即页面上「模型 JSON」文本框的内容       │
 │   算法： 从 order 里选一个【在所有路径中都出现】的变量作根          │
 │          按该变量取值切两个子路径集 → 生成一个 SEL 节点            │
 │          递归下降；单条路径收敛到常量时连到 0 / 1 常量节点          │
 │   节点： Import 变量  SEL 选择器  0/1 常量端子  Export 输出        │
 │   防御： 找不到公共根变量时返回带 error 标记的空图（旧版返回        │
 │          undefined，调用方随即抛 TypeError）                       │
 └────────────────────────────┬──────────────────────────────────────┘
                              ▼
 ┌───────────────────────────────────────────────────────────────────┐
 │ ⑤ 渲染与交互（ViewGen.js 主体）                                   │
 │   · joint.dia.Paper 主画布 + 第二个 Paper 作小地图 + mini-view 框  │
 │   · dagre 自动布局 joint.layout.DirectedGraph.layout(rankDir:'LR') │
 │   · paper.fitToContent → setContainerAndMini → 画布居中            │
 │   · 缩放/平移/滚轮、悬停删除工具、高亮、双击取消                   │
 │   · 双向： app.ELCreate (JSON→图) / app.ELDump (图→JSON)          │
 └───────────────────────────────────────────────────────────────────┘
```

## 3. 数据流全景（含双向回路）

```
 用户键入 RPN ─► LogicParser ─► ModelGen ─► ViewGen ─► app.ELCreate ─► JointJS 图
                    │              │           │            │              ▲
                 ite 树        路径集      图模型 JSON   ┌───┴──────────────┤
                    │              │           │         │ <textarea myModel>│
                    │              │           │         │  中间表示层       │
                    │              │           │         └───┬──────────────┘
                    │              │           │       app.load() / app.save()
                    │              │           │        (JSON→图 / 图→JSON)
                    └── 文件载入 ───┴───────────┴─► 纯前端闭环，无任何服务端往返

关键洞察：中间的 JSON 是【唯一的数据契约】。
         只要不破坏它，图形层可以零改动复用。
         量词信息不进入节点，而是顶层可选字段 quantPrefix —— 旧 JSON 不含
         该字段时按「无量词」处理，照常载入。
```

## 4. 数据结构契约（改造后以本文为准）

### `{value, order}` —— LogicParser → ModelGen → ViewGen 之间的契约

```jsonc
{
  "value": [                       // 立方体集合，每项是一个蕴含项
    { ".": ">", "a": ">", "b": "<" },   // a=1 且 b=0 时输出 1
    { ".": "<", "b": ">" }              // b=1 时输出 0（其余变量自由）
  ],
  "order": ["a", "b"]              // 出现过的变量全集
}
```

- `"."` 是终结标记，取值 `">"`（真 / 1）或 `"<"`（假 / 0）。
- `order` 为空表示该函数已化简为常量。
- 若 `value` 只有一项且无变量键，即常量模型。

### `{nodeArray, linkArray}` —— 模型 JSON（页面文本框内容）

```jsonc
{
  "nodeArray": [
    { "key": "0", "type": "0", "name": "Zero" },
    { "key": 1,   "type": "1", "name": "One" },
    { "key": 2,   "type": "Export", "name": "Out" },
    { "key": "a", "type": "Import", "name": "a" },
    { "key": 3,   "type": "SEL" }
  ],
  "linkArray": [
    { "from": "a", "frompid": "OUT", "to": 3, "topid": "SI" }
  ],
  "quantPrefix": [ { "var": "a", "type": "forall" } ]   // 可选，改造新增
}
```

- `type` 取值：`"0"` / `"1"` / `"Import"` / `"SEL"` / `"Export"`。
- 端口：`Import` 只有 `OUT`；`Export` 只有 `OUT`（作为入边目标）；`SEL` 有入端口 `SI`（选择输入）、`0`、`1`，出端口 `SO`（选中结果）、`N` / `P`。
- `quantPrefix` 为**可选顶层字段**，`type` 取 `"forall"` / `"exists"`。不含该字段的旧 JSON 一律按「无量词」处理。
- 节点模型上另有 `nodeType` 属性（不参与渲染）：固化节点类型，使「保存修改」改写 `label.text` 后「图转文本」仍能正确还原类型。旧图 / 旧 JSON 无该属性时回退读 `label.text`。
