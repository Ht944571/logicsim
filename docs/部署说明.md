# 部署说明

> 当前线上地址：**https://logicsim-edn.pages.dev/**
> 托管方式：**Cloudflare Pages**（直接上传模式，无构建步骤）
> 源码仓库：https://github.com/Ht944571/logicsim

### 为什么最终落在 Cloudflare Pages

计划阶段对比过几家，实测**国内可达性**后定在 Cloudflare：

| 候选 | 实测可达性 | 结论 |
|---|---|---|
| **Cloudflare Pages**（`pages.dev`） | **3/3** | ✅ 采用 |
| GitLab Pages（`gitlab.io`） | 3/3 | 可用，但要另注册账号 + 走 CI |
| GitHub Pages（`github.io`） | 2/3 | 不稳定 |
| Vercel（`vercel.app`） | **0/3** | ❌ 完全打不开，直接排除 |

选它的另两个理由：静态站点不需要构建；`wrangler pages deploy` 一条命令即可发布，
以后更新不必依赖任何平台网页操作。

### 更新线上内容

```bash
cd logicsim
export CLOUDFLARE_API_TOKEN=<你的 API 令牌>      # 权限：Account → Cloudflare Pages → Edit
export CLOUDFLARE_ACCOUNT_ID=<你的 Account ID>
export NODE_PATH="<wrangler 安装目录>/node_modules"
node <wrangler 安装目录>/node_modules/wrangler/bin/wrangler.js \
  pages deploy public --project-name=logicsim --branch=main

# 装 wrangler 时若报 esbuild EBUSY，加 --ignore-scripts：
#   npm install wrangler --ignore-scripts
```

更省事的做法是在 Cloudflare 后台把 Pages 项目**连上 GitHub 仓库**
（Workers & Pages → 该项目 → Settings → Build → Connect Git），
构建命令留空、输出目录填 `public`，之后每次 `git push` 自动发布。

## 1. 平台选型结论

计划阶段对比了三个免费静态托管方案，最终采用 **WorkBuddy 内置发布**。对比记录如下（供后续迁移参考）：

| 维度 | WorkBuddy 内置发布（**采用**） | Cloudflare Pages | GitLab Pages（原站） | Vercel |
|---|---|---|---|---|
| 免费额度 | 随工作区 | 无限带宽，500 次构建/月 | 无限站点，100 GB/月 | 100 GB/月，6000 构建分钟 |
| 构建要求 | 无需构建 | 无需构建 | 无需构建 | 无需构建 |
| 部署方式 | 工具一键发布本地目录 | Git 集成 / `wrangler` CLI | Git push 触发 CI | Git 集成 / CLI |
| 自定义域名 | 由平台提供子域 | 支持，自动 HTTPS | 支持，自动 HTTPS | 支持，自动 HTTPS |
| 国内访问 | 可用 | 较好 | 较差 | 差（`*.vercel.app` 普遍不可直连） |
| 上手成本 | **最低**（一条命令，无需账号配置） | 需 Cloudflare 账号 | 已有仓库即可 | 需账号 |

**选择理由**：站点是纯静态无构建项目，但**站点根目录是 `public/` 而非仓库根**——这一点在所有平台都要显式配置输出目录。内置发布可直接指定目录 `public/`，省掉账号注册、DNS 与构建配置，发布后再按需迁移。

**若后续需要迁移**，S3 / OSS / 国内云静态托管均为同一套「上传 `public/` 目录」的操作，迁移成本极低。

## 2. 部署配置

| 配置项 | 值 |
|---|---|
| 部署目录 | `logicsim/public`（**不是仓库根**） |
| 语言 / 运行时 | `static` |

## 3. 部署步骤（复现用）

### 前置：文件必须先落盘

发布工具是把目录**原样压缩上传**的。任何文件还在写入中就去发布，会传上去一个空壳。确认：

```bash
ls public/index.html public/style.css public/LogicParser.js public/ViewGen.js
ls public/lib/ public/assets/
```

### 发布

在对话中触发发布能力，指定目录为 `logicsim/public`，语言 `static`。

发布完成后会返回一个分享链接。**重复发布是覆盖式的**：同一目录再次发布，链接保持不变，内容被替换。

### 发布后自检

```bash
BASE=https://logicsim-edn.pages.dev
for f in "" index.html style.css LogicParser.js ViewGen.js \
         lib/joint.js lib/jquery.min.js lib/TsangerYuYangT-W03.ttf assets/SEL.svg; do
  echo "/$f -> $(curl -sL -o /dev/null -w '%{http_code} %{size_download}' "$BASE/$f")"
done
```

全部应为 `200` 且尺寸非零。特别注意字体文件（1.6 MB）与 `lib/joint.js`（1.1 MB）—— 这两个漏传会导致文字回退字体、画布完全不能渲染。

再跑一次真实浏览器的端到端验收：

```bash
E2E_URL=$BASE/ node tests/e2e-cdp.js tests/artifacts-live
```

## 4. 自定义域名方案

| 场景 | 操作 |
|---|---|
| 无自有域名 | 直接用平台提供的子域（**当前方案**） |
| 有域名，DNS 托管在 Cloudflare | 添加 CNAME 指向平台域名，自动签发证书 |
| 有域名，DNS 在其他服务商 | 在 DNS 服务商添加 CNAME，等待生效后签发证书 |
| 需国内合规（ICP 备案） | ⚠️ 自定义域名指向境外 CDN 仍属需备案情形。对公长期运营建议改用国内云静态托管并完成 ICP 备案 |

## 5. 与本地预览的差异

| 差异点 | 说明 |
|---|---|
| 协议 | 线上是 HTTPS，本地是 HTTP。代码中**没有任何 `fetch` / XHR**，因此 `file://` 直接打开也能跑，不存在同源限制 |
| 缓存 | 线上可能有 CDN 缓存。改动后若看到旧内容，强制刷新（Ctrl/Cmd+Shift+R） |
| 字体加载 | 1.6 MB 字体在弱网下首次加载稍慢，不回退则属正常 |
