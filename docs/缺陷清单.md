## 根因归纳（C1~C7 同源）

`LogicParser` 把「合法结果」与「错误信息」**统一用 `string` 返回**，调用方用 `typeof === 'string'` 区分。这导致合法结果空间与错误空间重叠：

- 合法结果本身可能是字符串（单变量 `a`、常量 `1`/`0`）→ 被当作错误（C2、C3）
- 合法结果可能是 `undefined`（空输入）→ 绕过错误判定进入下游崩溃（C1、C6）
- 错误信息只能用英文硬编码，且无法携带结构化错误码（C7）

**这是本次改造必须先处理的结构性缺陷**：若不先重构返回契约就加量词，量词会引入新的「结果可能是字符串」路径，同一批 bug 必然复发。

修复方式：返回统一结果对象 `{ ok:true, tree, quant }` / `{ ok:false, code, message }`，错误码与中文文案集中在 `LOGIC_ERRORS`。

### 本轮的两条方法论教训

1. **测试的期望值也会错。** 真值表用例把 `ModelGen` 的 `value.length`（立方体条数）当成了满足赋值个数，期望写成 9，实际正确答案是 6（一个立方体可覆盖多个赋值）。**失败后先用独立暴力求值判定哪边对，再改测试**——而不是改实现去迎合测试。已在测试注释里写明这个区别。
2. **测试自身写错会和真 bug 混在一起。** 门视图结构检查最初用"入边数"判断变量节点是否有连接，方向搞反了（变量是数据源，只有出边没有入边）→ 15 例全红。诊断顺序应是：先确认断言表达的是不是真的不变量，再看实现。
