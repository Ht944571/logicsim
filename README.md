# logicsim — 逻辑表达式图形化

把逻辑表达式编译成图形。**中缀/后缀两种写法都能输**，可以看成**选择器（MUX）网络**或**逻辑门电路**，自动列**真值表**，能导出 **SVG/PNG**，也支持在画布上**手动搭图连线**。

**在线使用**：https://logicsim-diagram.app.workbuddy.host/

> 本仓库由 **kuangdash** 的 [logicsim](https://gitlab.com/kuangdash/logicsim) 改造而来，保留其全部原有功能。图形库为 JointJS v3.3.1（MPL-2.0）。原仓库未附许可证，请在再分发前确认授权。

## 快速开始

本项目**没有构建步骤**——纯静态文件，克隆后直接起一个静态服务器即可。

```bash
git clone <本仓库地址> && cd logicsim
python -m http.server 8080 --directory public
# 打开 http://localhost:8080
```

也可以直接双击 `public/index.html`（代码中没有任何网络请求，`file://` 协议下同样能跑）。

> ⚠️ 站点根目录是 **`public/`**，不是仓库根目录。部署时输出目录要指向 `public`。

## 用法

### 两种输入写法

**中缀写法**（默认，直接写数学式）：

```
(a AND b) -> fe
a OR b AND NOT c
∀x(a AND b)
```

| 运算符 | 别名 | 含义 |
|---|---|---|
| `NOT` | `!` `~` `¬` | 非 ¬ |
| `AND` | `&&` `&` `∧` `·` `*` | 与 ∧ |
| `OR` | `\|\|` `\|` `∨` `+` `,` | 或 ∨ |
| `->` | `=>` `IMPLY` `→` | 推出 → |
| `<->` | `<=>` `IFF` `↔` `≡` | 等价 ↔ |
| `∀x(...)` | `ALL x(...)` `FORALL x(...)` | 全称量词 |
| `∃x(...)` | `EX x(...)` `EXISTS x(...)` | 存在量词 |

优先级 `¬` > `∧` > `∨` > `→` > `↔`；推出是右结合。拿不准就加括号。
量词的作用范围必须用括号或点号界定：`∀x(a AND b)` 或 `∀x. a`（点号只绑定紧随的一元项）。

**后缀写法**（逆波兰）：操作数在前、操作符在后。

| `.` 与 | `,` 或 | `<` 非 | `>` 推出 | `=` 等价 | `?` 存在量词 ∃ | `!` 全称量词 ∀ |
|---|---|---|---|---|---|---|

`a b .` 表示 a 与 b；`a b . x ?` 即 ∃x.(a ∧ b)。

两种写法可以随时切换，解析结果完全等价（由 `tests/e2e-cdp.js` 的 6 组对照用例守着）。

### 两个视图

| 视图 | 画什么 | 回答什么问题 |
|---|---|---|
| **选择器** | 化简后的 **MUX 网络**（SEL 节点） | 这个函数最少要几级选择才能实现 |
| **逻辑门** | 原表达式的**与/或/非门电路**（标准逻辑符号） | 这个式子长什么样 |

两者对同一表达式在逻辑上完全等价，可以切着对照看。切换会按表达式重新生成图形。

### 其它功能

- **实时预览**：打字即出图（防抖 400ms）。打到一半语法还不完整时**保留上一张图**，只在输入框下方标红报错并指出出错位置。
- **真值表**：右侧「真值表」页，列出化简后自由变量的全部取值组合，输出为 1 的行标绿，并给出恒真/恒假的判断。
- **导出**：工具栏「SVG」（矢量，可无损放大，适合放进 PPT）与「PNG」（2 倍分辨率）。导出会自动裁到内容范围、去掉网格、把图标内联成 data URI。
- **手动编辑**：工具栏「手动添加」放与门/或门/非门/变量/常量；节点可自由拖动；从输出端按住拖到输入端即可连线，拖已连线的端点可改接。连线方向有校验（只允许输出→输入，不允许自环）。
- **本机持久化**：表达式与图形自动存在浏览器 `localStorage`，关掉页面再打开还在。**注意这不会同步到云端**，换电脑就没了；要长期保存请用「导出文件」。
- **画布**：网格对齐、滚轮缩放、拖拽平移、「适应窗口」一键回到全貌。快捷键 `Alt+↑/↓` 缩放、`Alt+[/]` 折叠右侧面板、`Ctrl/Cmd+Enter` 立即解析。

### 已知限制

- 变量数上限 8，化简后路径数上限 4096；超出会给出中文提示而不是卡死。
- 选择器视图的化简是**路径枚举式**的，变量越多路径增长越快（最坏 2ⁿ）。这是原实现的算法特性，未替换算法。
- 真值表最多展开 4096 行（12 个变量）。
- 切换视图会按表达式重新生成图形，手工添加的节点不会保留（界面会提示）。
- 窄屏（<900px）下图形不自动缩放到视口，可用滚轮或「适应窗口」。
- 右侧「元素标签」显示在节点上方、原本承载节点类型；改造后类型改由独立属性承载，因此改名不再破坏「图转文本」。
- 选择器视图用变量名当节点键，若把变量命名为 `2` 会与输出端的键冲突（原实现遗留，为保持数据契约兼容未改动）。

## 视觉规范

界面配色取自一组参考插画的**实测采样**（18 张图约 70 万像素，细量化后按色相族取代表值），
不是凭观感估的。定义在 `public/style.css` 的 `:root`，画布侧的同源副本在
`public/ViewGen.js` 的 `CANVAS_PALETTE`。

| 令牌 | 值 | 来源 |
|---|---|---|
| `--paper` | `#FBF9F6` | 暖白纸底（实测 `#FCFCFC` / 暖调 `#FCF0E8`） |
| `--ink-1` / `--ink-2` | `#2A1F2E` / `#544458` | 头发紫 `#544458` **占参考图 23.4%**，是绝对主色 |
| `--brand` | `#4C4C7A` | 校服藏青（实测 `#585888`，暗部 `#38385C`） |
| `--bow` | `#7A3A4E` | 领结酒红（实测暗部 `#482834`，饱和度仅 0.35） |
| `--sage` / `--sage-soft` | `#5F7A62` / `#E4E8D8` | 奶油苔绿 —— 参考图里唯一的绿，借来当"真值/通过"色 |
| `--blush` | `#D89C9C` | 腮红点缀 |

间距一律走 `--sp-1..8`（4px 基准），字号走 `--fs-2xs..2xl`，圆角 `--r-xs..lg`，阴影 `--sh-1..3`。

**改配色时的三条硬规矩**：

1. **`style.css` 与 `ViewGen.js` 的 `CANVAS_PALETTE` 必须同时改** —— 画布是 JointJS 直接写 SVG，CSS 变量到不了那里。
2. **底色可配的组件，文字色要用 `textOn(fill)` 按明度取反**。原先节点文字写死白色，底色一改就会出现"白字白底"。
3. **形状不能画进 `standard.Path` 的 `body.d`** —— 该形状设置尺寸时会用自身默认路径覆盖掉你的值（D 形会静默变成矩形）。基类统一用 `standard.Rectangle`，造型交给自定义选择器 `gate`。

> 参考插画带第三方水印，**只取色、不嵌入**；界面上的图形要么复用项目已有资产，要么用 CSS 绘制。

## 项目结构

```
public/                     ← 站点根目录
  index.html                页面结构（中缀/后缀、双视图、标签页面板）
  style.css                 样式（CSS 变量 + Flexbox + 三档响应式断点）
  LogicParser.js            逻辑内核：LogicParser / ModelGen / ViewGen / TruthTable
                            纯逻辑无 DOM 依赖，可直接用 Node 跑
  InfixParser.js            中缀 → 后缀翻译（带字符位置的错误报告）
  GateView.js               运算符树 → 逻辑门电路图模型 + 门的几何与符号
  ViewGen.js                界面与渲染：JointJS 画布、交互、导出、持久化
  latch.json                示例模型（锁存器）
  lib/                      第三方依赖，全部本地化，无 CDN
  assets/                   图标与节点图
tests/                      Node 直接运行的测试，无需浏览器
docs/                       改造文档
```

### 数据管线

```
                     ┌── 后缀写法 ──────────────────┐
输入（中缀 / 后缀）──┤                              ├─► LogicParser ─┬─► ModelGen ─► 路径集 ─► ViewGen ─► 选择器视图
                     └── InfixParser 翻译成后缀 ────┘                 │
                                                                     └─► 运算符树 ─► GateViewGen ─► 逻辑门视图
```

- **`InfixToRPN(src)`** — 中缀 → 后缀，同时产出运算符 AST。**下游零改动**：翻译完就走完全相同的既有管线，所以不可能引入回归。
- **`LogicParser(rpn, opts)`** — 单栈求值造树。默认产 MUX / ite 树 `{S,"0","1"}`；`opts.nodeKind==='gate'` 时产运算符树 `{op,a,b}`，`opts.keepQuantifier` 保留量词节点而不就地展开。
- **`ModelGen(tree)`** — 递归展开 + 交集合并 → 路径集 `{value, order}`。
- **`ViewGen(pathSet)`** → 选择器图模型；**`GateViewGen(opTree)`** → 门电路图模型。两者输出同一套 `{nodeArray, linkArray}` 契约。
- **`TruthTable(vars, cubes)`** — 由路径集枚举真值表。

`{value,order}` 与 `{nodeArray,linkArray}` 是层间数据契约。量词信息**不进入节点结构**（它消去了被绑定变量，图上没有对应节点），而是作为模型 JSON 的可选顶层字段 `quantPrefix`。

## 改造要点

**第一轮（结构与能力）**：

1. **输入健壮性重构** — 原实现用「返回值是不是字符串」区分「解析结果」与「错误信息」，导致单变量 `a`、常量 `1`/`0` 被误判为错误，纯空白输入还会抛未捕获异常使页面崩溃。改为统一结果对象 `{ok,tree,quant}` / `{ok,code,message}`。
2. **全称/存在量词** — 新增 `?`(∃) / `!`(∀)，求值走 `∃x φ = φ[x:=0] ∨ φ[x:=1]`、`∀x φ = φ[x:=0] ∧ φ[x:=1]`。选 `?`/`!` 而非字母 `E`/`A`，因为分词器把任何非操作符 token 都当变量名。
3. **现代 UI 与响应式** — Flexbox 重写骨架，CSS 变量，三档响应式断点，中文错误提示。

**第二轮（交互与可视化）**：

4. **中缀输入** — 降低输入门槛，`(a AND b) -> fe` 直接可写。翻译成后缀后复用既有管线，因此量词等能力自动可用。
5. **实时预览 + 内联报错** — 打字即出图；语法不完整时保留上一张图，标红并指出出错位置。
6. **逻辑门视图** — 标准逻辑符号（与门 D 形、或门月牙形、非门三角+圆）。参数化 `LogicParser` 让它能额外产出运算符树，默认行为一字未改。
7. **真值表 / 导出 SVG·PNG / 手动连线 / localStorage 持久化**。

详细说明见 [`docs/改造说明.md`](docs/改造说明.md)，业务与数据结构见 [`docs/业务梳理.md`](docs/业务梳理.md)，回滚步骤见 [`docs/回滚方案.md`](docs/回滚方案.md)。
